# 学习工作流

本文件定义 obsidian-learning 的六条工作流。所有步骤都以 Markdown 笔记为产物，
只在用户明确同意后才移动或删除笔记。

## 1. 建档（必须先行）

在开始采集任何资料之前，先写或更新一条 `mission` 笔记：

```yaml
---
title: 学习目标 · <主题>
type: mission
status: active
tags: []
aliases: []
created: YYYY-MM-DD
---
```

正文回答四个问题：

- **为什么学**：1–3 句，落到真实世界的结果（"能在 Y 场景独立完成 X"），不写抽象的"想了解"。
- **成功看起来像什么**：2–4 条可观察、可验证的标准（"不看资料复述 SDIO 初始化流程""独立调试并通过一次摄像头采集"）。
- **约束**：时间、已有基础、可用设备、偏好。
- **范围之外**：明确不学什么，保护注意力。

Mission 说不清楚的，先反问用户，不要替用户编造动机。

## 2. 采集（入 Inbox 或建 Source）

- 网页、PDF、笔记、代码、随手想法：先落到 `01-Inbox/`（保留来源 URL 与日期），或直接整理为 `source` 笔记。
- 只有完成了"消化"步骤的采集物才算真正入库；Inbox 可以暂存，但定期清空。

## 3. 研究提炼

每份来源按顺序处理：

1. **读完整份**来源，删除感觉不重要的部分，保留有信息量的内容。
2. 写 `source` 笔记：来源元数据、关键论点摘录（带 block ID 便于引用）、与当前 mission 的相关性。
3. 把核心观点拆成一条条 `concept` 笔记；新术语进 `glossary`。
4. 概念之间用双链互连（`prerequisites`、相关概念）。

判断某个观点是否值得写进笔记，问三个问题：

- 这个想法在来源的不同上下文里重复出现吗？
- 换成领域内任何一位专家，会不会说同样的话？
- 它能预测来源对新问题的回答吗？

通过两个以上才写；只出现一次的当背景；都不满足的丢弃。
来源之间矛盾时，两条都保留并互相链接，写明各自证据，不悄悄选一边。

## 4. 课程

- 学习路线 = `moc` 笔记中的有序列表，每项对应一条 `lesson`。
- 每条 `lesson` 只教一件事，3–5 分钟可读完，一次性给出一个"看得见的收获"。
- 先按用户的最近发展区定难度：宁可每秒都被挑战一点，不要一次塞满。

## 5. 实践与复习

- 用户完成练习后写 `practice` 笔记：做了什么、观察到什么、哪里错了、证据是什么。
- 只有存在练习或真实使用证据，才在 `learning-record` 中提升掌握程度。
- 复习时间由 `review_after` 驱动，规则见 `references/review-method.md`。

## 6. 整理与归档

- 把 Inbox 中已消化的内容归位到 Areas / Projects / Resources。
- 归位后更新所属 `_MOC.md`（增补或调整入口）。
- `archived` 状态只用于确实不再维护的笔记；删除文件前必须由用户明确同意。

## 会话节奏

- 一次会话只做一件事：建档、采集、提炼、一课、或一轮复习，不包办全部。
- 每节课后，问一句"刚才这个是否刚好？"来校准难度，并把这个信号记入 `NOTES` 或下一条 `learning-record`。
