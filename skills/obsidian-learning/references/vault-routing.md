# Vault 路由规则

目录结构遵循 `obsidian-knowledge-base` 的 PARA 变体约定（`00-Home.md`、`01-Inbox/`、`02-Areas/`、`03-Projects/`、`04-Resources/`、`05-Archive/`、`99-Templates/`），本文件只规定学习场景下的路由决策，不重复目录定义。
本 skill 只在目标目录是 Obsidian Vault 时使用（工作目录即 Vault，或用户显式指定路径）。

## 归属判断

| 内容 | 去哪 |
| --- | --- |
| 随手想法、未消化的网页/PDF/代码 | `01-Inbox/` |
| 长期领域学习（无硬截止） | `02-Areas/<领域>/` |
| 有明确目标、时限、验收标准的学习计划 | `03-Projects/<项目>/` |
| 原始资料、官方文档、书籍、术语 | `04-Resources/` |
| 不再维护的内容 | `05-Archive/`（先问用户） |

判断原则：**宁可晚归档，不可随手乱放**。拿不准就进 Inbox，整理时再决定。

## MOC 更新

- 每个 Area / Project 根部有 `_MOC.md`（`type: moc`）。
- 新增或移动笔记后，检查所在层级的 `_MOC.md` 是否需要补/改入口。
- MOC 只放「入口」，不放全文：用双链 + 一句话说明。

## 命名建议

- 文件名用短横线或直接中文均可，但必须唯一（Obsidian 全局按文件名链接）。
- `_MOC.md` 固定这个名字，便于工具识别。
- 同领域的课程可以 `05-<序号>-<短名>.md` 前缀保持顺序；概念笔记不要编号，改名成本高。

## 模板

- `99-Templates/` 存放各类笔记模板（见主 skill 的 Phase 2 约定）。
- 模板使用 Obsidian 原生占位符（`{{title}}`、`{{date}}`），不依赖 Templater。

## 边界

- 归位、移动、删除前先展示方案并取得用户同意；不批量自动操作。
- 不主动修改 `.obsidian/` 配置；不承诺任何第三方插件可用。
